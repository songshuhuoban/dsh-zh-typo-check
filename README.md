# 中文检查（DSH 输入框插件）

在 DSH 输入框里标出中文错别字和半角标点。规则保底、模型补语义，模型按需下载，全程本地运行。

---

## 一、它怎么工作

```
按键
 └─ L0 规则        微秒级，同步出下划线        成语误字、半角标点、的还→的话
    └─ 停手 400 ms
       └─ 宿主模型   MLM 掩码打分，补语义错   还→话、在→再、因→应……
```

- **L0 永远可用**。41 KB 的规则表，判定是确定性的，不需要任何下载。
- **模型是增强，不是前提**。没装模型、模型坏了、推理运行时缺失——输入框里的规则检查都照常工作（有专门的韧性测试守着这条）。

原理上不用手写判据：把句子里的某个字遮住，让一个在中文错字语料上微调过的语言模型猜这里该是什么字。猜得比原字强得多，就说明原字多半写错了。判据只有两个数值：模型给原字和给候选字的分数差。

## 二、效果

同一套 75 句语料（错别字、成语误字、标点、正常文本各若干），留出集按 `test` 隔离：

| 方案 | 精确率 | 召回率 | F1 | 正常句误报 |
| --- | --- | --- | --- | --- |
| 只有规则 | 96.3% | 61.9% | 75.4% | 0/30 |
| 规则 + 模型（全集） | **100.0%** | **79.5%** | **88.6%** | **0/30** |
| 规则 + 模型（留出集） | **100.0%** | **80.0%** | **88.9%** | **0/15** |

召回率 +17.6 个点，误报为零。

单句耗时约 **97–127 ms**（模型加载在内存里时），首次检查含载模型约 0.8–1.5 s。

## 三、模型与下载

| | |
| --- | --- |
| 模型 | `Xenova/macbert4csc-base-chinese`（MacBERT 在 SIGHAN 错字语料上微调，ONNX int8） |
| 体积 | 103.6 MB + 分词器 429 KB |
| 许可证 | Apache-2.0 |
| 线路 | `hf-mirror.com` 优先，`huggingface.co` 兜底 |
| 校验 | 逐文件 SHA-256，失败删半成品换线路 |
| 存放 | `$DSH_HOME/profiles/<profile>/models/zh-typo-check/` |

设置在 **设置 → 插件 → 中文检查**（插件设置页里的一个标签页）：显示状态、进度条、下载/取消/删除。删除后自动退回纯规则。

为什么不把模型放进浏览器：同一个模型，宿主进程原生推理 **21 ms/次**，浏览器 WASM **135 ms/次**——差 6.4 倍，而且页面侧还要多下载 13.6 MB 运行时。所以推理在宿主，页面只发一个 HTTP 请求。

### 插件装好后怎么确认它活着

```bash
curl http://127.0.0.1:64024/zh-typo-model/selftest
```

逐层自检 `runtime / model-files / lexicon / l1 / tokenizer / check`，每层报 `ok` 和实际数值。

注意：命令行 `curl` 拿到的 404 不代表路由不存在——这台服务器对未鉴权请求统一回 404
（随便一个不存在的路径也是 404，根路径是 401）。要在浏览器里看，或者看设置页的实际状态。

## 五、已知局限

1. **人名/专有名词会被误改。** 词典里没有名字，模型永远偏好常见字。
   `斯成`→`办成` 这类误报调不掉（那个字和邻字凑巧能成词）。
   办法是按上下文忽略：忽略一次只影响这一处，不会波及所有同字。
2. **只做单字替换。** `包斯成`→`汉堡` 这类整词错误报不出来。
3. **长句只覆盖抽样位置。** 每次检查最多打分 7 个位置（延迟上限），
   超长文本按步长均匀取样，不是逐字扫。
4. **不是独立测试集。** 75 句是我按真实输入场景写的开发集，绝对数字会偏高；
   有意义的是规则与模型的**相对差异**，以及留出集上的一致结论。

## 六、文件

```

src/editor.mjs      DOM ↔ 草稿偏移映射
src/client.js       输入框浮层 + 设置页（构建时把上面两个模块拼进去）
src/tokenizer.mjs   BERT 分词器
src/infer.mjs       掩码打分
src/lexicon.mjs     词表与近音字表（"改完得像话"约束）
src/l1.mjs          同音候选（A 路）
src/checker.mjs     A/B 两路合流
bundle/             可发布的插件目录
tools/              构建与验证脚本
NOTES.md            逐轮实验记录（含被否掉的方案）
```

## 七、验证边界

- ✅ 规则判定、偏移映射、模型下载/校验/分发/删除、分词、推理、判定质量：全部离线验证
- ✅ 浮层与设置页的**注册**：槽位检查确认（`settings.plugins.tab` 有 `zh-typo-check`，order 20，排在内置的"全部"之后）
- ✅ 宿主路由**已完成注册**：启动日志显示 `route registered at /zh-typo-model/`
- ✅ 下划线渲染与气泡：用户已在浏览器中确认（见第 20 条笔记）
- ⚠️ 命令行 `curl` 探测不到路由：这台服务器对**未鉴权请求**统一回 404
  （`/zzz-nonsense-1234` 也是 404，根路径是 401），所以 curl 的 404 不能用来判断路由是否存在。
  要探测就得在浏览器里打开，或看设置页的实际状态。

模型尚未下载时，输入框只跑规则（微秒级）；在 **设置 → 插件 → 中文检查** 里下载之后，
停手 400 ms 会再跑一次模型检查。
