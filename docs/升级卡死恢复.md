# 升级卡在“停止并移除旧版”

DSH 0.2.2-rc.1 更新运行中的插件时可能停在移除步骤，留下“依赖仍是旧版、启用列表已移除、安装目录消失”的中间状态。此时新的插件代码还未安装，反复点更新或刷新页面不能结束宿主侧等待。

## 当前已经卡住

1. 保存其他会话的未发送草稿，完全退出 DSH，包括托盘进程。
2. 在本仓库目录运行：

   ```powershell
   .\tools\repair-upgrade.ps1
   ```

3. 出现 `Recovery completed` 后正常启动 DSH。在中文检查详情确认版本为 0.3.1、插件已启用。

脚本使用 DSH 官方 CLI 从 npm 安装精确版本，并补回启用记录。执行前备份 profile 配置，执行后核对配置与已有模型哈希；不删除锁、账号、会话、模型或配置，不改 DSH 的 app.asar。若 DSH 桌面主进程仍在运行，会拒绝执行。

默认 CLI 路径为 `D:\deepseek-harness\resources\runtime\cli\bin\dsh.cmd`。不同安装位置可传 `-DshCli`；非默认 profile 可传 `-ProfileDirectory`。先加 `-PlanOnly` 可只查看操作计划。

若原生运行时安装脚本被拦截，按 DSH 提示允许 `onnxruntime-node@1.30.0` 后重试；脚本不会覆盖已有的脚本拒绝规则。失败时保留备份和诊断，不强行删除锁或结束进程。

## 后续升级

0.3.0 及更早版本一旦加载原生推理库，即使禁用插件，DLL 仍可能被 Host 占用，因此使用上述“退出后升级”路径。只禁用旧插件不能保证解决；当前已卡住的事务也应先完全退出宿主。

以后升级时可用 `-Version` 指定目标版本；脚本默认安装 `0.3.1`。

0.3.0 的 27 MB 整句模型需在插件设置中单独下载；已有错字模型与偏好会保留，旧版明确关闭的整句开关不会被脚本打开。

## 本次实机结果

2026-11-10，用户保存草稿并退出 DSH 后，真实 desktop profile 已通过该脚本恢复为 **0.3.0、已启用**。恢复过程约 9 秒，检查偏好文件未改变，已有的两份模型文件哈希保持一致，原配置备份保留在当前 profile 的 `.plugin-manager/repair-backups/`。

重新启动 DSH 后，已确认实际插件界面为 0.3.0，并完成选定的整句模型下载与校验，显示“已就绪 · 本地运行”。真实宿主检查接口验证：原问题句检出，正常混排和英文对照不提示，原有“还→话”纠错仍有效。实机冒烟时间 `2026-11-10T09:19:59Z`，细节见 `data/upgrade-recovery-verification.json`。

0.3.1 已把原生推理移至独立子进程，卸载时等待进程退出，避免本插件继续占用 DLL。第一次从旧版切换到修复版仍须退出 DSH 后安装。根因与对照见[排查记录](DSH-更新器卡死-报障.md)，发布与实机升级记录见[0.3.1 交付记录](release-0.3.1.md)。宿主对更新失败的界面处理仍待 DSH 修复。
